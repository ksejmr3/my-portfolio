# Portfolio Typography Guide

> 적용 범위: 개인 포트폴리오 전체. 기존 PROCESS 01–06의 구조·콘텐츠·스크롤 기능은 변경하지 않는다.

## 1. Font families

| 역할 | 서체 | CSS font-family |
|---|---|---|
| 한국어 본문, UI | Pretendard | `'Pretendard', sans-serif` |
| 영문 본문, 숫자, 메타 | Inter | `'Inter', sans-serif` |
| 영문 포인트 이탤릭 | Lora Italic | `'Lora', Georgia, serif` + `font-style: italic` |

- Playfair Display Italic은 대체 후보로만 둔다. 한 페이지에서 Lora와 Playfair를 혼용하지 않는다.
- 폰트 로딩 실패 시 시스템 대체 서체를 사용한다.
- 실제 폰트 파일 또는 합법적 웹폰트 소스가 확인되기 전에는 존재하지 않는 로컬 파일 경로를 만들지 않는다.

## 2. Type scale (desktop baseline)

| 토큰 | 사용처 | 크기 | 두께 | 행간 | 자간 |
|---|---|---|---|---|---|
| `display-xl` | 히어로 초대형 제목 | `clamp(64px, 9vw, 160px)` | 600–700 | 0.92–1.02 | -0.045em |
| `display-lg` | 섹션 대형 타이틀 | `clamp(48px, 6vw, 112px)` | 600–700 | 0.98–1.08 | -0.04em |
| `heading-lg` | 섹션 내 제목 | `clamp(32px, 3.2vw, 56px)` | 600 | 1.12–1.2 | -0.035em |
| `heading-md` | 소제목 | `clamp(24px, 2vw, 36px)` | 600 | 1.2–1.3 | -0.025em |
| `body-lg` | 핵심 설명 | `clamp(17px, 1.2vw, 20px)` | 400–500 | 1.65–1.8 | -0.015em |
| `body` | 일반 본문 | `16px` | 400–500 | 1.7–1.85 | -0.01em |
| `caption` | 보조 설명 | `13–14px` | 400–500 | 1.5–1.65 | 0–0.01em |
| `eyebrow` | 섹션 번호·메타 | `12–14px` | 500–600 | 1.4–1.5 | 0.06–0.12em |

수치는 디자인 출발점이다. 실제 렌더링과 한글/영문 조합을 보고 조정한다. 자간은 CSS `letter-spacing` 기준.

## 3. Readability rules

- 한국어 본문은 16px 미만으로 내려가지 않는 것을 기본으로 한다. 모바일에서는 15–16px 이상을 우선한다.
- 긴 본문은 최대 폭 55–68ch 또는 약 560–680px 범위에서 가독성 검수한다.
- 문단 사이 간격은 대략 본문 행간의 0.8–1.2배를 시작점으로 한다.
- 제목과 설명 사이 간격은 16–32px, 큰 섹션의 주요 요소 간 간격은 32–64px에서 조정한다.
- 영문 올캡스 메타에는 약간 넓은 자간을 허용하되, 한글 본문에는 과도한 양의 자간을 쓰지 않는다.
- 초대형 제목은 의도적인 압축 행간을 사용하지만, 본문은 절대로 제목처럼 압축하지 않는다.
- 이탤릭 강조는 영문 키워드나 짧은 문구에만 사용한다. 한글 문장 전체에 이탤릭을 적용하지 않는다.
- 모바일에서 제목이 잘리거나 가로 스크롤이 발생하면 크기와 줄바꿈을 우선 조정한다.

## 4. Hierarchy examples

- `PROJECT OPENING`: Inter/Pretendard 기반의 대형 산세리프 타이틀.
- `THE CHALLENGE`, `KEY SOLUTIONS`, `MY CONTRIBUTION`: 공통 섹션 타이틀 규칙 적용.
- 강조가 필요한 영어 단어 1개: Lora Italic 적용 가능. 모든 제목에 기계적으로 넣지 않는다.
- 역할, 기간, 번호: Inter 기반 작은 메타 타이포그래피.
- 한국어 문제·해결·기여 설명: Pretendard, 충분한 행간과 본문 폭 유지.

## 5. Implementation boundaries

1. 먼저 현재 프로젝트의 폰트 로딩 방식, 기존 CSS 토큰, 타이포그래피 사용 현황을 조사한다.
2. 중복되거나 충돌하는 폰트 선언을 정리할 개선안을 제시한다.
3. 기존 PROCESS 01–06의 구조, 패널, 설명, 이미지, GSAP pin/scrub, 자동 전환, 라이트박스는 절대 변경하지 않는다.
4. 타이포그래피 전역 변경이 PROCESS 레이아웃에 영향을 줄 수 있으므로, 실제 적용 시 PROCESS는 명시적으로 보호하거나 영향 범위를 분리한다.
5. 1920 / 1440 / 1024 / 390px에서 줄바꿈, 잘림, 대비, 가로 overflow, 폰트 로딩을 검수한다.
6. 기존 미커밋 변경사항을 보존하며 사용자 승인 없이 commit/push/merge/reset/clean/stash 하지 않는다.

## 6. Review checklist

- [ ] 제목의 크기 위계가 모든 섹션에서 일관적인가?
- [ ] 한국어 본문의 행간이 답답하지 않은가?
- [ ] 본문 줄 길이가 지나치게 길지 않은가?
- [ ] 영어 이탤릭 강조가 드물고 의미 있게 사용되는가?
- [ ] 섹션 번호·메타의 스타일이 일관적인가?
- [ ] 모바일에서 제목 잘림과 가로 overflow가 없는가?
- [ ] PROCESS 기존 시각·기능이 유지되는가?

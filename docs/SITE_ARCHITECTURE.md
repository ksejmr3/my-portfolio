# 개인 포트폴리오 V2 구조 설계

상태: 전체 사이트 구조 제안. INTRO와 SELECTED WORKS의 정적 레이아웃을 구현했고, 3차 작업에서 별도 프로젝트 폴더의 실제 비주얼로 WORK를 보강했다. 레퍼런스의 화면 리듬과 현재 콘텐츠의 증거 수준을 기준으로 한다.

## 페이지 구조

`/`는 INTRO → SELECTED WORKS → ABOUT/WORKING STYLE → SKILLS → CONTACT로 구성한다. 프로젝트 상세는 `/work/hyundai-motorstudio`, `/work/vivienne-westwood`, `/work/cos`의 개별 페이지를 권장한다. 각 상세 끝에는 WORK 목록과 다음 프로젝트로 이동하는 링크를 둔다. 현대 연구 자료가 길고 다른 두 사례는 아직 자료가 부족하므로 한 페이지에 세 상세를 모두 이어 붙이는 것보다 개별 페이지가 탐색과 읽기에 유리하다. 라우팅 도구는 실제 구현 단계에서 결정한다.

| 구간 | 목적과 핵심 콘텐츠 | 이미지·배치 | 인터랙션과 연결 |
|---|---|---|---|
| INTRO | 이름, 직무 방향, 검증된 한 문장 소개 | 큰 제목과 작은 보조 문구, 여백 중심 | 기본 스크롤. WORK 앵커/링크 |
| SELECTED WORKS | 세 사례의 종류와 차이를 빠르게 비교 | 각 프로젝트의 확정 대표 이미지가 준비되면 크기·비율이 다른 카드 또는 행 | hover/focus는 CSS. 각 상세로 링크 |
| ABOUT / WORKING STYLE | 경력 전환과 작업 방식, 근거 있는 자기소개 | 본인 사진 또는 실제 작업 과정 이미지 | 일반 세로 흐름. SKILLS로 이어짐 |
| SKILLS | 도구 나열보다 프로젝트에서 한 일과 연결 | 과한 아이콘 장식 없이 묶음별 텍스트 | 각 사례 증거로 링크 |
| CONTACT | 확인된 이메일/연락 링크 | 단순한 큰 마무리 문장 | 메일 링크와 상단 이동 |

## 상세페이지 정보 위계

- **현대:** 프로젝트 개요·팀/개인 범위 → 조사(시장·자사/경쟁사·설문/인터뷰) → 관찰과 문제 정의 → 퍼소나/여정/린캔버스 중 의사결정에 필요한 근거 → 정보 구조와 사용자 흐름 → 디자인 시스템과 최종 UI → 실제 구현 증거 → 검증·한계. 각 분석표는 원본 이미지와 확대 보기를 함께 둔다. 같은 결론을 반복하는 보드는 접어서 추가 자료로 보낸다. 조사 결과와 기획 가설을 구분한다.
- **Vivienne Westwood:** 범위 → 브랜드 해석의 근거 → 콘셉트와 비주얼 시스템 → 최종 시안 → 실제 구현 증거(준비된 경우) → 회고. 전용 에셋이 없으므로 디자인 자료 확보 뒤 상세 배치를 확정한다.
- **COS:** 범위 → 콘셉트 → 타이포·컬러·이미지 결정 → 최종 시안 → 실제 구현 증거(준비된 경우) → 회고. 구현 전에는 DEVELOPMENT를 완료 챕터로 표시하지 않는다.

## React 구조 제안

```text
src/
  App.jsx                 # 향후 라우트 연결
  components/
    SiteHeader.jsx
    SiteFooter.jsx
    ProjectCard.jsx
    CaseSection.jsx
    EvidenceFigure.jsx    # 원본 이미지, 캡션, 확대 링크/대화상자
  pages/
    HomePage.jsx
    HyundaiPage.jsx
    ViviennePage.jsx
    CosPage.jsx
  data/
    projects.js           # 검증된 메타데이터와 에셋 출처
  styles/
    base.css
    tokens.css
    layout.css
    components.css
```

현재 `src/App.jsx`는 `IntroSection`과 `WorkSection`을 연결한다. `ProjectCard`와 `src/data/projects.js`가 WORK 세 행을 구성한다. 상세페이지, 공통 푸터, 조사 자료 확대 보기는 아직 구현하지 않았다. 프로젝트 이미지의 실제 비율을 유지하며 모바일에서는 2열 장면을 1열로 바꾼다.

## 인터랙션·개발 순서

1. 프로젝트별 확정 콘텐츠와 이미지 export 목록을 검증한다. 현대의 개인 역할, 수치 출처, 조사·가설 구분을 확인한다.
2. 공통 타입/색/여백 토큰과 내비게이션, 홈의 정적 구조를 구현한다. 키보드 포커스와 모바일 흐름을 동시에 설계한다.
3. 현대 상세의 증거 이미지, 캡션, 확대 보기와 사례 서사를 먼저 구축한다. 이어 두 개인 프로젝트의 확보된 자료만 노출한다.
4. 정적 화면이 완성되면 녹화에서 확인된 장면 전환 중 콘텐츠 이해에 도움이 되는 동작을 선택한다. 단순 등장/hover는 CSS, 스크롤 진행률에 정확히 묶인 재배치가 필요할 때만 GSAP ScrollTrigger를 설치한다. 프로젝트 간 링크는 우선 표준 탐색으로 구현한다.
5. 모바일, 역방향 스크롤, reduced-motion, 이미지 로딩 후 레이아웃을 검수한다. 현재 영상에서는 이러한 동작이 확인되지 않았으므로 레퍼런스의 구현 사실로 설명하지 않는다.

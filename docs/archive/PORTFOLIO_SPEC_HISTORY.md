Playfair Display는 현재 일부 구현에서 사용되지만, 이후 공통 타이포그래피 정리 시 Lora Italic과 역할을 통합하는 방향을 우선 검토한다.

- **검증 필요**: Playfair Display가 브랜드별 고유 표현으로 남아야 하는 구간이 있는지 실제 화면 기준으로 확인한다.

### 3.2 타입 스케일

| 역할 | 데스크톱 제안 범위 | 모바일 제안 범위 | 기준 |
|---|---:|---:|---|
| Display XL | `clamp(72px, 9vw, 160px)` | `clamp(52px, 15vw, 92px)` | 히어로·마무리 대형 제목 |
| Display LG | `clamp(56px, 6.6vw, 120px)` | `clamp(44px, 11vw, 72px)` | 주요 섹션 제목 |
| Section Title | `clamp(44px, 4.8vw, 80px)` | `clamp(34px, 8.5vw, 52px)` | 섹션 내부 제목 |
| Project Title | `clamp(40px, 4.2vw, 70px)` | `clamp(30px, 7vw, 46px)` | 프로젝트·영상 제목 |
| Heading | `clamp(22px, 1.8vw, 30px)` | `18px–22px` | 질문·소제목 |
| Body Large | `17px–20px` | `16px` | 핵심 설명 |
| Body | `16px–18px` | `15px–16px` | 일반 본문 |
| Caption | `13px–14px` | `11px–12px` | 보조 설명·캡션 |
| Eyebrow / Label | `12px–13px` | `9px–10px` | 번호·메타·레이블 |

- **확정**: 본문은 데스크톱에서 16–18px, 모바일에서 15–16px을 기본으로 한다.
- **확정**: Caption은 13–14px, Eyebrow / Label은 12–13px을 기본 기준으로 한다.
- **확정 예외**: HYUNDAI 보호 도입부·SELECTED SOLUTIONS 캡션은 9px을 유지한다. 수정 가능한 개인 프로젝트·보드 캡션은 같은 서체·굵기·상대 자간·행간·간격 체계의 11px이다. 일반 본문·설명까지 이 크기를 적용하지 않는다.
- **확정**: 큰 제목은 공통 Display 체계를 사용한다.
- **확정 예외**: INTRO와 WORK INTRO처럼 의도적인 연출형 제목은 별도 크기와 줄바꿈을 허용한다.
- **제안**: 본문 line-height는 1.65–1.75, 제목은 0.88–1.05, 한글 본문 자간은 `-.02em` 이하의 과도한 압축을 피한다.

- **확정**: 전체 화면형 섹션과 일반 콘텐츠형 섹션에 동일한 padding을 강제하지 않는다.
- **제안**: 기존의 `4.2vw`, `5vw`, `6.5vw`, `7vw`, `8.3vw`는 일반·케이스·편집형 콘텐츠라는 목적에 따라 위 세 가지 폭 기준으로 정리한다.

#### 현재 구현된 상세 간격 규칙

- Hyundai SELECTED WORKS의 동일 구조 그룹은 `--work-group-space: clamp(44px, 4vw, 72px)`를 구분선 위·아래에 사용한다. 900px 이하에서는 `clamp(32px, 5vw, 48px)`로 줄이며, 콘텐츠 높이는 고정하지 않는다.
- 목업 아래 캡션은 `--work-caption-space: clamp(16px, 1.4vw, 22px)`를 기본으로 한다. 휴대폰이 노트북 하단보다 내려오는 Exhibition 복합 목업은 캡션 겹침을 피하기 위해 데스크톱에서만 추가 여백을 둔다.
- 섹션 번호와 라벨은 같은 수평선에 놓고 CSS 간격 20px을 유지한다. 본문·MY ROLE의 서체와 행간은 공통 역할을 따르되 프로젝트 고유 타이틀과 Figma 자산 내부 타이포그래피는 변경하지 않는다.
- 복합 목업은 노트북을 주 요소로 두고 휴대폰을 오른쪽 앞에 일부만 겹친다. 화면 크기에 따라 휴대폰 위치를 조정하며, 단일 노트북 목업에는 휴대폰을 추가하지 않는다. 560px 이하에서는 두 기기를 세로로 배치한다.

### 6.1 2026-10-21 화면 검수 반영

다음 수치는 첨부 화면의 가독성 및 배치 문제를 개선하기 위해 실제 CSS와 JSX에 반영했다. 기존 이미지·영상 자산과 주요 GSAP 인터랙션은 보존했다.

| 구간 | 적용 기준 |
|---|---|
| Hyundai Challenge | 화면 높이에 맞춘 중앙 정렬, 제목 `clamp(56px, 5.4vw, 100px)`, 본문 16–19px / `1.72`, 문제 요약 18–23px; 케이스 gutter 기준 3열 |

### 6.2 2026-10-21 전체 화면 레이아웃 재검수 기록

아래 내용은 해당 날짜의 작업·검수 기록이며 현재 브라우저 검수 상태를 뜻하지 않는다.

- INTRO와 WORK 도입부의 안내 문구는 자연스러운 문장 흐름으로 정리했다. Hyundai 본문은 자연 줄바꿈을 사용하고, 공통 본문에는 `word-break: keep-all`, `overflow-wrap: break-word`, 16–18px 및 약 1.72 행간을 적용했다.

### 6.3 2026-10-21 목업 자산 검토 및 전시 모바일 합성

- `public/images/mockups/iphone-front-mockup.png`는 1611×3323 정면 프레임이며 화면 내부에 `Free iPhone 18 Pro Mockup` 샘플 그래픽이 포함되어 있다. 프레임을 전체 이미지로 그대로 얹지 않는다. Hyundai 전시의 기존 모바일 Figma 미리보기를 화면 창에 배치하고, 프레임은 화면 영역을 마스크로 제외한 바깥 테두리만 위에 합성하며 Dynamic Island는 별도 레이어로 유지한다. 화면 창은 프레임 비율을 기준으로 좌측 4.2%, 상단 1.7%, 너비 91.6%, 높이 96.6%로 정의했다. Chromium 캡처에서 프레임·화면 합성과 샘플 문구 가림을 확인했으며, 픽셀 단위의 원본 프레임 경계 비교는 수행하지 않았다.
- `SELECTED WORKS → 02 / EXHIBITION EXPERIENCE`에서 기존 별도 모바일 설명 칼럼을 제거하고, 노트북을 주 비주얼로 유지한 채 정면 스마트폰을 데스크톱에서는 우측 하단(`right: 2%; bottom: 20%`, 폭 `clamp(150px, 15.5vw, 220px)`)에 겹치는 구조로 변경했다. 1200px 이하에서는 조금 안쪽으로 옮기고, 900px 이하에서는 노트북 아래 중앙에 배치한다. 모바일 화면의 기존 Figma 이미지, 이미지 마스크, 양방향 자동 스크롤/reduced-motion 동작과 노트북은 유지했다. 화면 설명은 `MOBILE / FIGMA SCROLL` 캡션으로 축약했다.

- 확인한 코드상 타이포그래피는 Hyundai 주요 본문에 16–19px 및 약 1.72 행간, 한글 어절 줄바꿈을 사용한다. 본 작업에서는 별도 전체 폰트 재설계를 하지 않았고, PROCESS와 다른 인터랙션 구간의 타이밍·핀 길이도 변경하지 않았다. Chromium에서 선택한 전시 작업 구간을 1920×1080, 1440×900, 1024×768, 768×1024, 390×844로 렌더링했다. 다섯 크기에서 문서 가로 overflow는 측정되지 않았고, 900px 이하의 전화기 아래 배치를 확인했다. 1440px와 390px 화면에서 노트북·휴대폰 합성 결과와 화면 안 샘플 문구가 가려지는 것을 확인했다. 브라우저에서 전체 섹션의 타이포그래피·배경·pin 동작, 각 프로젝트 자동 스크롤의 양방향 전 구간은 이번 확인 범위에 포함되지 않았다.

## 9. 향후 최적화 계획

최적화는 시각적 통합 구현과 반응형 검수가 끝난 뒤 진행한다.

1. **이미지**: Figma WebP 분할 이미지의 총 용량, 노트북·휴대폰 PNG 크기, 장표 원본 해상도와 실제 표시 크기를 측정한다.
2. **영상**: MP4의 해상도·코덱·비트레이트·포스터·재생 정책을 점검한다.
3. **GSAP**: ScrollTrigger 중복, refresh 횟수, pin 위치, 리사이즈·이미지 로드 이후 안정성을 확인한다.
4. **스크롤 렌더링**: rAF 자동 스크롤이 화면 밖에서 정지하는지, 유지한 pin·scrub 구간이 저사양 환경에서 프레임을 유지하는지 확인한다.
5. **폰트**: Pretendard와 Google Fonts의 로딩, FOUT/FOIT, 대체 서체 상태를 확인한다.
6. **번들**: GSAP 및 simple-icons의 tree-shaking, JS/CSS 청크 크기, 사용하지 않는 자산을 점검한다.
7. **Web Vitals**: LCP, CLS, INP를 실제 배포 또는 로컬 프로덕션 빌드에서 측정한다.
8. **접근성**: 키보드 포커스, video controls, 챗봇 패널, reduced-motion, 390px 가로 overflow를 점검한다.

최적화는 무조건적인 압축보다 목업 선명도, 영상 재생 안정성, 기존 인터랙션의 품질을 우선한다.

## 12. 현재 구현 상세 및 검증 상태

### SKILL

- 2026-11-02 최종 지시에 따라 3D 로고·로고 전용 데이터·ScrollTrigger·sticky 및 전용 스크롤 높이를 제거했다.
- `src/components/SkillSection.jsx`는 `src/data/skillTools.js`의 기존 6개 기술 그룹과 모든 문구를 정적으로 표시한다. ABOUT 앞의 순서를 유지한다.
- `src/styles/skill-section.css`는 내용에 따른 자연 높이와 공통 섹션 여백을 사용한다. 전체 그리드는 최대 636px로 중앙에 놓고, 데스크톱·태블릿 3열·700px 이하 2열을 적용한다. 도구 목록은 데스크톱 18px·모바일 16px, 라벨은 12–13px다. 상단 보조 라벨을 유지하고 하단 문구는 삭제했다.

### ABOUT

- `src/components/AboutSection.jsx`, `src/styles/about-section.css`, `src/data/aboutPhotos.js`가 소개와 5색 카드 아코디언 및 사진 필름스트립을 구성한다.
- 데스크톱은 ScrollTrigger pin 진행률로 5개 카드가 순차 전환되고 역방향도 진행률에 따라 복원된다. 직접 선택 시 해당 진행 구간으로 스크롤을 맞춘다.
- 카드별 필름스트립은 사진 배열을 반복해 오른쪽에서 왼쪽으로 이동한다. 활성 카드가 화면에 보이고 사진 로드가 끝난 경우에만 RAF가 동작하며, 드래그·스와이프 뒤 3초 정지 후 현재 위치에서 재개한다.
- 700px 이하와 reduced-motion 설정에서는 자동 스크롤 인터랙션 대신 접근 가능한 정적/수동 구성을 사용한다. `aboutPhotos.js`는 `public/images/about/web/`의 WebP 39개를 참조하며, `originals/`의 JPG 39개는 보존 원본이다.

### AI VIDEO CONTENTS

- 최종 확정 레이아웃은 소개 + 가로 영상 + 세로 영상의 3열 구성이다. `src/styles/ai-video-contents.css`에서 800px 이하 단일 열로 전환한다.
- `src/data/aiVideoContents.js`의 영상 비율은 각각 16:9와 9:16이다. `src/components/AIVideoContents.jsx`가 autoplay, muted, loop, playsInline, metadata preload로 표시한다. 섹션 IntersectionObserver가 진입 시 재생을 요청하고 이탈 시 음소거·정지한다. SOUND 버튼은 선택 영상의 음소거를 해제한다. 현재 구현에는 reduced-motion에 따른 영상 자동재생 제외 분기가 없다.
- 현재 확정 디자인에는 pin·scrub 기반 영상 전환이나 하단 진행선이 없다.

### HYUNDAI 목업 자산

- `src/components/HyundaiProjectPreview.jsx`는 `public/images/hyundai/selected-works/web/desktop/`의 WebP 7개와 `.../mobile/`의 WebP 8개를 순서대로 표시한다. 원본 PNG는 별도 경로에 보존되어 있다.
- 목업의 타일 로딩은 노출된 이미지의 진행에 맞춰 다음 타일을 decode하는 구조다. 확인 당시 WebP 15개는 로컬 미추적 상태였으며 실제 런타임 참조이므로 최종 배포 커밋에 포함되어야 한다.

### 검증 현황 및 한계

- 앞선 확인 기록상 프로덕션 빌드는 성공했고 기존 Vite 500kB 초과 청크 경고가 남아 있다. 이 문서 갱신 중에는 빌드를 실행하지 않았다.
- 전체 화면 Chrome 자동 검수는 Chrome 실행 오류로 완료되지 않았다. 따라서 반응형 뷰포트 전체와 전체 스크롤 흐름을 검증 완료로 표시하지 않는다.
- 스크롤 위치 복원은 사용자가 현재 정상 동작을 확인했다고 보고했다. 이는 사용자 확인이며 이번 작업에서 별도 실측하지 않았다.
- 아래 구현·상태 설명은 이번 문서 갱신 당시 로컬 파일과 제공된 검수 기록을 기준으로 하며 이후 변경 시 재확인이 필요하다.

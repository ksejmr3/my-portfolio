## 2. INTRO 말풍선 겹침과 위치 수정

기존 말풍선은 프리뷰의 **사진 영역**을 덮었다. 모바일의 기존 충돌 검사는 주로 실제 텍스트 줄·버튼·영상 등을 대상으로 하므로, 사진만 덮는 경우도 실제로 남아 있었다. 이 부분을 숨김·재예약으로 처리하지 않고 **위치 계산**으로 해결했다.

프리뷰가 실제 viewport에 보이고 말풍선과 가로 영역이 겹칠 때, 말풍선 하단이 프리뷰 상단보다 **16px 위**가 되도록 `--assistant-hint-bottom`을 계산한다. 프리뷰가 사라지거나 가로 충돌이 없으면 기존 bottom72px/64px로 복귀한다. 등장 시 기존 translateY8px 애니메이션을 포함해도 두 영역은 겹치지 않는다.

기존 `scroll` passive 리스너1개·resize 리스너·rAF 예약을 그대로 이용했다. ResizeObserver 인스턴스를 추가하지 않고 기존 observer가 프리뷰 크기 변화도 감지하도록 했다. 신규 타이머·스크롤 리스너·말풍선 문구·장식은 없다. 말풍선의 opacity/translateY **.28초** 전환, 마스코트 크기·부유·위치, 수동 챗봇 패널은 유지했다.

5개 해상도 모두 실제 말풍선이 보이는 상태에서 프리뷰와의 겹침이 없음을 확인했다. 모바일에서도 단순히 마스코트를 숨겨 통과시킨 결과가 아니라, INTRO의 말풍선과 런처가 보이면서 프리뷰가 가려지지 않는 상태다. 프리뷰를 벗어났다가 돌아와도 진행 중인 표시 회차를 재시작하지 않는다.

## 9. GSAP / ScrollTrigger 보존

`HyundaiCaseStudy.jsx`는 시작 시점과 동일하다. 기여 항목의 기존 동작은 **각 항목 y72·opacity0→y0·opacity1**, `start:'top 94%'`, `end:'top 58%'`, `scrub:true`이다. 이미지는 해당 항목과 함께 나타난다. 별도의 이미지 전용 타임라인이나 정방향 fade-out을 새로 만들지 않았다. 정방향 퇴장은 기존처럼 viewport 밖으로 나가는 흐름이며 역방향에서는 같은 scrub으로 되돌아간다.

5개 해상도에서 네 항목 각각 진입 전→중간→완료→중간→진입 전→완료를 확인했다. 완료 후 화면 밖 퇴장도 확인했다. 실제 wheel의 느린 이동·빠른 이동, 정·역방향에서 네 항목 모두 opacity1에 도달했고 가로 넘침은 없었다. 각 reveal 구간의 거리는 기존 **viewport 높이의36%**, duration1 그대로다.

레이아웃 높이가 달라져 후속 항목·CLONE·ABOUT의 절대 문서 좌표는 자연스럽게 이동했다. 이 이동을 애니메이션 거리 변경으로 오해하지 않았다. 기존 이미지 load·ResizeObserver의 refresh가 좌표를 갱신하며, GSAP 코드나 보정용 새 타임라인은 필요하지 않았다. INTRO/PROFILE/WORK·HYUNDAI 진입·SELECTED SOLUTIONS·PROCESS의 기존 start/end는 유지했다. 항목별 진입·완료·자연 퇴장 좌표는 부록에 기록한다.

## 12. 빌드·Git 및 검증 파일

- `npm.cmd run build`: **성공(exit0)**. Vite8.3.0,72 modules,710ms. CSS118.57kB / JS970.61kB. 기존500kB 초과 경고는 유지한다. 새 의존성·lint 스크립트는 추가하지 않았다.
- `git diff --check`: **통과(exit0)**. 기존 LF→CRLF 안내와 실제 whitespace 오류는 구분한다.
- Git HEAD 전체 diff와 이번 변경을 구분해 시작 해시와 대조했다. 허용한 소스3개와 최신 명세 외 기존 파일은 보존했다.
- Commit / Push / Vercel 배포 / reset / clean / 다른 저장소 수정 없음.
- 이번 전용 Chrome(9346)·Vite(5175)는 검증 후 종료했다. 사용자 브라우저·다른 서버는 종료하지 않았다.
